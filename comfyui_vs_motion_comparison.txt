====================================================

ISSUE: Getting [1, 32, 9, 104, 60] instead of [1, 32, 11, 104, 60]

======================

   ComfyUI WanVaceToVideo:

CRITICAL DIFFERENCE IDENTIFIED:
===============================

The main difference is in VAE encoding input format:

ComfyUI: Uses 4D tensors directly
- inactive: [T, H, W, 3] -> vae.encode() -> [1, 16, T//8, H//8, W//8]
- reactive: [T, H, W, 3] -> vae.encode() -> [1, 16, T//8, H//8, W//8]
- reference_image: [1, H, W, 3] -> vae.encode() -> [1, 16, 1, H//8, W//8]

Motion Pipeline: Converts to 5D tensors first
- inactive: [T, H, W, 3] -> permute+unsqueeze -> [1, 3, T, H, W] -> vae.encode() -> [1, 16, T//8, H//8, W//8]
- reactive: [T, H, W, 3] -> permute+unsqueeze -> [1, 3, T, H, W] -> vae.encode() -> [1, 16, T//8, H//8, W//8]
- reference_image: [1, H, W, 3] -> permute+unsqueeze -> [1, 3, 1, H, W] -> vae.encode() -> [1, 16, 1, H//8, W//8]

POTENTIAL ISSUE:
================

The 5D tensor conversion might be causing the VAE to produce different temporal dimensions. The VAE might be expecting 4D input format like ComfyUI, but we're giving it 5D input.

SOLUTION:
=========

Change Motion Pipeline to use 4D tensor encoding like ComfyUI:

```python
# Instead of:
inactive_5d = inactive[:, :, :, :3].permute(3, 0, 1, 2).unsqueeze(0)
inactive_latent = self.vae.encode(inactive_5d)

# Use:
inactive_latent = self.vae.encode(inactive[:, :, :, :3])
```

This should fix the dimension mismatch and produce the expected [1, 32, 11, 104, 60] instead of [1, 32, 9, 104, 60].
